# ProCam 17 Studio — Android / Kotlin

Новый независимый проект камеры и редактора. Android 8.0+ (API 26), compile/target SDK 34.
Интерфейс на русском, тёмная тема, золотой акцент. Камера работает через CameraX.

## Что реализовано

- Задняя/фронтальная камера, предпросмотр, фокусировка касанием, кнопка съёмки.
- Live-обработка света, цвета, деталей и приблизительное портретное боке
  до нажатия затвора. Отдельный поток ImageAnalysis, отбрасывание устаревших
  кадров, ограничение до 10 обновлений/с и до 480 px по длинной стороне.
  Частота зависит от телефона; без совместимой комбинации потоков используется
  обычное превью с явным сообщением. Полная обработка снимка остаётся доступна.
- Импорт фото через системный выбор файла без широкого доступа к галерее.
- Корректировка ориентации и зеркальных EXIF-преобразований.
- Свет/тени: локальная яркость, мягкий подъём теней и сжатие светов.
- Детализация: пороговое усиление микроконтраста, более слабое на предполагаемой коже.
- Цвет: умеренное потепление/насыщенность с эвристической защитой тона кожи.
- Портрет: встроенная ML Kit Selfie Segmentation, маска человека, размытие фона.
  Если человек не обнаружен, результат остаётся без боке с пояснением.
- Три пресета и четыре регулятора. Регуляторы применяются кнопкой; пресеты — сразу.
- Удержание фото показывает исходный кадр, отпускание — обработанный.
- JPEG 95% в `Pictures/ProCam17`; на Android 8–9 запрашивается разрешение записи.
- HDR-серия по выбору: нейтральный, примерно −1 EV и +1 EV. Значения зависят
  от диапазона камеры. Нормализация экспозиции, взвешенное объединение в линейном
  RGB, консервативное подавление двоения. При обнаружении движения — средний
  по экспозиции кадр. При отсутствии поддержки — одиночный снимок.
- Последовательная обработка: кнопки блокируются на время операции; ошибки
  показываются пользователю; незавершённые записи в галерее удаляются.

## Честные ограничения

Это собственная приближённая обработка, **не** реализация закрытых Apple Smart HDR,
Deep Fusion или Photonic Engine. Имена из исходного ТЗ сохранены в некоторых классах.
Обработка одного JPEG не восстанавливает потерянные детали и не выполняет
многокадровое шумоподавление Deep Fusion. HDR-серия — JPEG exposure bracketing:
нет RAW, оптического потока или полноценного выравнивания кадров. Используйте
неподвижный телефон и статичную сцену; быстрые движения и вращение могут дать
артефакты, несмотря на защитный откат. Это экспериментальный режим.

Боке рассчитано на людей, не на предметы; тонкие волосы и сложный фон требуют
проверки. Live-превью приблизительное: YUV-конверсия BT.601, уменьшенное разрешение,
потоковая маска и более простой blur. Оно не гарантирует точного совпадения с
JPEG камеры и финальной обработкой. Полноценное HDR из трёх экспозиций применяется
только после съёмки. Длинная сторона
результата ограничена 2048 px для памяти и скорости. Видео, RAW, ручной ISO,
выдержка, оптический зум и вспышка в этой версии не реализованы.

Модель сегментации включена в APK, фотографии не загружаются в облако.
Приложение не запрашивает разрешение INTERNET. ML Kit — сторонняя библиотека,
её сведения об обработке данных: https://developers.google.com/ml-kit/terms

## Сборка APK через GitHub Actions

1. Распакуйте архив. Загрузите **содержимое папки ProCam17 в корень** репозитория,
   а не папку целиком. В корне должны находиться `settings.gradle.kts`, `app/`
   и `.github/workflows/build_apk.yml`. Не пропустите скрытую папку `.github`.
2. Для старого `procam-new` замените существующий `build_apk.yml` и одноимённые
   исходники файлами новой версии. Удалите старые дополнительные workflow,
   если они собирают другую структуру. Используйте отдельную ветку при необходимости.
3. Откройте **Actions → Build Android APK → Run workflow** или выполните push
   в `main`/`master`. Учётная запись должна разрешать выполнение Actions.
4. Только после успешных unit tests, Android lint и `assembleDebug` появится
   артефакт **ProCam17-debug-APK**. Скачайте ZIP и извлеките `app-debug.apk`.
5. Установите APK на Android-телефон; разрешите установку из выбранного источника.
   Debug-APK подписан автоматически; он не предназначен для Google Play.

Если старая версия с тем же applicationId подписана другим ключом, Android
откажет в обновлении. Удаление старого приложения позволит установить новый APK,
но удалит его внутренние данные. Версия приложения: 2.1.0, versionCode: 3.

### Почему новая сборка не даёт ложный Success

CI явно устанавливает JDK 17, Android SDK 34 и Gradle **8.7**. Gradle Wrapper
генерируется официальной задачей `gradle wrapper`, затем выполняется
`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`.
Нет `|| true`, заглушек `javac -version` и скрытия ошибок.
APK проверяется на наличие, ненулевой размер и целостность ZIP.
Загрузка с `if-no-files-found: error`; SHA-256 входит в артефакт.

В исходном архиве нет готового бинарного `gradle-wrapper.jar`. CI не зависит от
его наличия: устанавливает фиксированный Gradle через официальный `gradle/actions`
и создаёт полноценный Wrapper, доступный отдельным артефактом **Gradle-Wrapper-8.7**.
Это сознательно указано, чтобы отсутствие бинарного файла не выглядело готовой
локальной конфигурацией Wrapper.

## Локальная сборка

Нужны JDK 17, Android SDK Platform 34 / Build Tools 34.0.0 и Gradle 8.7.
Укажите SDK в `local.properties` (`sdk.dir=...`) либо `ANDROID_HOME`.
Из корня проекта:

```text
gradle wrapper --gradle-version 8.7 --distribution-type bin
```

Windows:

```text
gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

macOS/Linux:

```sh
chmod +x gradlew
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`.
Локальную папку можно открыть в Android Studio после генерации Wrapper.

## Проверки перед передачей

В поставку включены JVM-тесты математического ядра: размытие сравнивается
с наивным эталоном, проверяются границы изображения, нулевые настройки,
клиппинг каналов, веса экспозиции и гамма-преобразование.
CI запускает их вместе с Android lint и компиляцией.

**При создании этого архива Java / Android SDK отсутствовали. APK не был
скомпилирован, JVM-тесты и Android lint фактически не запускались, работа
на телефоне не проверена.** Выполнена структурная проверка исходников,
ресурсов, зависимостей конфигурации и архива. Первый CI-прогон обязателен.
Если он завершается ошибкой, скачайте `Build-reports` и журнал упавшего шага;
не считайте наличие исходников подтверждением успешной компиляции.

## Проверка на телефоне

Подробный сценарий: `TESTING.md`. Если приложение падает, нужен журнал
